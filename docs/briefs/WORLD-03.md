## Design decisions
- Registry remains authoritative. Persistent mutations go through a generation-checked hydrator API and commit immediately; save-at-boundary therefore sees current data before unload. Nodes only project copied state. There is no second pending-state store to serialize or flush.
- Authored manifest records gain optional `entities: [{uuid, node_path, initial_state}]` (default empty). UUIDs are globally unique across the manifest; node paths are nonempty relative descendant paths (no `.`/`..`/absolute paths, unique within a chunk). Initial state is validated against registry limits; no Nodes. Manifest validation rejects malformed descriptors atomically. Runtime checks ensure each unsuppressed target exists and supports `apply_persistent_state(state: Dictionary) -> void` and `set_interaction_enabled(enabled: bool) -> void`. These callbacks are authored projections, must not mutate registry data, and must preserve their hydrated state in `_ready`.
- `collected: true` or `destroyed: true` is a data tombstone. Hydration removes that authored projection before scene entry; later backtracking never recreates it as interactive. No loot grants, mission rewards or enemy behavior are added.
- Loader gets an optional final `entity_lifecycle: Object = null` configure parameter. Protocol: `prepare_chunk(chunk_id: String, generation: int, instance: Node3D) -> bool` before scene entry, `activate_chunk(chunk_id: String, generation: int, instance: Node3D) -> bool` after scene entry and before manager acknowledgement/publishing loader activation, and `retire_chunk(chunk_id: String, generation: int, instance: Node3D) -> void` before scene teardown or rejected preparation. Recheck generation/instance after callbacks. Retained-instance re-entry also prepares again, since pre-unload invalidates prior bindings. Activation accepts PRELOADING: enabling hydrated projections and manager acknowledgement occur synchronously without a process-frame gap. This ordering permits a projection rejection to fail/retry without leaving the manager falsely ACTIVE.
- `EntityHydrator` is a transient RefCounted service, configured once with `(registry: EntityRegistry, manifest: ChunkManifest, manager: WorldManager) -> bool`. It connects to `manager.chunk_pre_unload` and exposes the loader protocol above. It may retain transient Nodes in runtime bindings; the registry never does.
- API: `commit_entity_delta(uuid: String, delta: Dictionary, generation: int) -> bool` rejects unknown/unbound/suppressed IDs and stale generations before authority mutation; then calls registry's new `try_commit_state_delta` and reprojects copied state. Accepted tombstones disable/remove projections and revoke bindings immediately. `get_runtime_entity(uuid: String) -> Node3D` returns only current valid bound nodes, otherwise null. `get_bound_entity_count() -> int` exposes current live bindings. `interactions_invalidated(payload: Dictionary)` emits once per currently bound chunk when pre-unload revokes its bindings; payload includes chunk_id, retirement lifecycle_generation and `entity_uuids` array. Invalidating consumers must not revive retired generations.
- Prepare validates the whole chunk (all descriptors, target nodes, existing ownership and data) before registering any missing defaults or invoking projections. Use registry prepared snapshot APIs for an atomic merge of missing defaults; existing records always win. On projection callback invalidation/failure, disable/revoke all staged bindings; never overwrite newer registry progress. Valid authored defaults may remain registered after a later canceled activation, since identity/data are independent of live scenes.
- Registry adds `try_commit_state_delta(uuid, delta) -> bool` sharing existing validation/merge logic; existing void method delegates to it unchanged. This lets projection code distinguish a rejected authority update from an accepted no-op without duplicating merge rules.
